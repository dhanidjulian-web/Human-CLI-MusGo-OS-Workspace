# AI PROVIDER SPECIFICATION

Version: 1.0.0
Status: ACTIVE
Project: Human CLI

---

# 1. PURPOSE

Dokumen ini mendefinisikan sistem AI Provider dan Model Routing Human CLI.

Sistem harus mendukung:

- multiple AI providers
- multiple API keys per provider
- multiple models per provider
- free model
- paid model
- BYOK
- automatic provider detection
- automatic model detection
- fallback
- model priority
- API key rotation
- health check
- rate-limit handling
- manual model selection
- custom provider
- custom endpoint

---

# 2. CORE PRINCIPLE

Provider dan Model adalah dua entitas berbeda.

Provider:

contoh:

- OpenRouter
- NVIDIA
- Mistral
- xAI
- GitHub Models
- custom provider

Model:

contoh:

- model-a
- model-b
- model-c

Satu provider dapat memiliki banyak model.

Satu provider dapat memiliki banyak API key.

Custom provider harus menyediakan minimal:

- model prefix

# 9. MULTIPLE API KEYS

Contoh:

Key B

- id

- masked value
- status
- priority
- createdAt
- lastUsedAt
- lastSuccessAt
- lastFailureAt
- cooldownUntil
- usage metadata

Secret asli hanya disimpan di Secure Storage.

# 12. API KEY PRIORITY

Setiap key memiliki priority.

Default:

1

Namun health status tetap dapat mengalahkan priority.

Contoh:

Key A priority 1 tetapi RATE_LIMITED.

Key B priority 2 dan ACTIVE.

Router menggunakan:

Key B.

# 17. ROUTING MODES

Human CLI memiliki empat mode utama:

1. AUTO_FREE
2. AUTO_BALANCE
3. AUTO_BYOK
4. MANUAL

---

# 18. AUTO_FREE

Tujuan:

Memprioritaskan model gratis.

Priority:

1. FREE
2. HEALTH
3. CAPABILITY
4. CONTEXT
5. LATENCY
6. PROVIDER PRIORITY

Paid model tidak boleh digunakan jika masih tersedia kandidat FREE yang memenuhi requirement.

Jika tidak ada model FREE yang memenuhi requirement:

System meminta:

fallback permission

atau mengikuti global fallback policy.

---

# 19. AUTO_BALANCE

Tujuan:

Mencari keseimbangan antara:

- cost
- quality
- latency
- availability
- capability

Priority:

QUALITY

↓

COST

↓

LATENCY

↓

HEALTH

↓

PROVIDER PRIORITY

---

# 20. AUTO_BYOK

Tujuan:

Menggunakan credential milik user.

Provider/model dapat dipilih otomatis.

Namun credential harus berasal dari credential user sendiri.

Prioritas:

1. active BYOK credential
2. model capability
3. health
4. cost
5. latency

---

# 21. MANUAL

User memilih:

Provider

dan

Model

System menggunakan pilihan tersebut.

Tidak boleh melakukan silent fallback ke model lain.

Jika gagal:

Tampilkan error.

User dapat memilih fallback secara manual.

---

# 22. FALLBACK

Fallback harus memiliki ordered candidate list.

Contoh:

1. Model A
2. Model B
3. Model C
4. Model D

Jika A gagal:

B

Jika B gagal:

C

dst.

---

# 23. FALLBACK CONDITIONS

Fallback diperbolehkan untuk:

- timeout
- temporary network error
- provider unavailable
- rate limit
- transient server error

Fallback tidak boleh otomatis untuk:

- invalid credentials
- permission denied
- malformed request
- unsupported capability

kecuali policy secara eksplisit mengizinkan.

---

# 24. SILENT FALLBACK

AUTO modes:

Boleh silent fallback.

Namun UI harus dapat menunjukkan:

Original:

Provider A / Model A

Fallback:

Provider B / Model B

MANUAL:

Tidak boleh silent fallback.

# 30. MODEL CAPABILITY MATCHING

---

# 31. CONTEXT WINDOW MATCHING

Jika context membutuhkan:

100K tokens

Model dengan:

32K

tidak boleh dipilih.

Router harus mencari model yang memenuhi minimum context requirement.

---

# 32. COST CONTROL

Router harus menghormati:

- maximum request cost
- profile budget
- workflow budget

Jika cost tidak diketahui:

pricing state:

UNKNOWN

Jangan menganggap:

UNKNOWN = FREE.

---

# 33. RATE LIMIT

Jika provider memberikan:

429

atau equivalent rate-limit signal:

Credential:

RATE_LIMITED

dan diberikan cooldown.

Router dapat:

rotate credential

atau

fallback model/provider.

---

# 34. RETRY

Retry hanya untuk transient error.

Default:

max 2 retries

Retry harus menggunakan exponential backoff.

Retry tidak boleh menyebabkan infinite loop.

---

# 35. TIMEOUT

Setiap request harus memiliki timeout.

Timeout harus configurable.

Default harus aman untuk mobile network.

Long-running workflow dapat memiliki timeout berbeda.

---

# 36. HEALTH CHECK

Provider health dapat diperiksa melalui:

- lightweight validation
- model listing
- minimal generation request

Health check tidak boleh menghabiskan banyak quota.
