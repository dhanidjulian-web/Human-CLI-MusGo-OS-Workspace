# AI ROUTER SPECIFICATION

Version: 1.0.0
Status: ACTIVE
Project: Human CLI

---

# 1. PURPOSE

AI Router adalah komponen yang menentukan:

- provider mana yang digunakan
- model mana yang digunakan
- API key mana yang digunakan
- kapan melakukan retry
- kapan melakukan fallback
- kapan melakukan key rotation
- bagaimana memprioritaskan model
- bagaimana menghormati mode Free / Balance / BYOK / Manual
- bagaimana menangani model/provider yang gagal

AI Router tidak melakukan inference secara langsung.

Router hanya mengambil keputusan dan menyerahkan eksekusi kepada AI Request Engine.

---

# 2. RESPONSIBILITY

AI Router bertanggung jawab atas:

- candidate discovery
- candidate filtering
- candidate scoring
- model selection
- credential selection
- fallback
- retry
- cooldown
- health-aware routing
- capability matching
- context matching
- cost policy
- routing decision metadata

AI Router tidak bertanggung jawab atas:

- UI
- conversation persistence
- GitHub
- sandbox
- skill execution
- library indexing
- raw provider implementation

# 8. AUTO_FREE

Tujuan:

Memaksimalkan penggunaan model gratis.

Primary priority:

FREE

Secondary:

HEALTH

CAPABILITY

CONTEXT

LATENCY

QUALITY

---

# 9. AUTO_FREE RULE

Model FREE hanya boleh dipilih jika memenuhi minimum task requirement.

Contoh:

Task membutuhkan:

TOOL_CALLING

Model gratis:

TEXT only

Maka model tersebut tidak valid.

Router mencari kandidat lain.

---

# 10. AUTO_FREE FALLBACK

Default behavior:

FREE model

↓

FREE fallback

↓

PAID fallback jika policy mengizinkan

Jika paid fallback tidak diizinkan:

return NO_ELIGIBLE_MODEL.

---

# 11. AUTO_BALANCE

Tujuan:

Mencari keseimbangan:

QUALITY

COST

LATENCY

AVAILABILITY

CAPABILITY

Default weighting:

Quality: high

Cost: high

Latency: medium

Availability: high

---

# 12. AUTO_BYOK

AUTO_BYOK hanya menggunakan credential milik user.

Prioritas:

ACTIVE credential

↓

HEALTH

↓

CAPABILITY

↓

MODEL QUALITY

↓

COST

↓

---

# 13. MANUAL

User menentukan:

provider

dan

model.

Credential dapat:

- dipilih manual
- atau menggunakan active credential provider

Tidak boleh melakukan silent fallback.

Jika gagal:

return error.

# 14. CANDIDATE DISCOVERY

Router membangun candidate list dari:

- preferred models
- fallback models
- provider catalog
- discovered models

Candidate harus:

enabled

dan

available

---

# 15. CANDIDATE FILTERING

Filter minimum:

1. provider enabled
2. model enabled
3. credential available
4. capability compatible
5. context compatible
6. cost compatible
7. health acceptable

---

# 16. CAPABILITY FILTER

Jika task membutuhkan:

CODE

model harus mendukung CODE.

Jika task membutuhkan:

VISION

model harus mendukung VISION.

Jika task membutuhkan:

TOOL_CALLING

model harus mendukung TOOL_CALLING.

---

# 17. CONTEXT FILTER

Router menerima:

requiredContextTokens

Model harus memiliki:

contextWindow >= requiredContextTokens

Jika tidak:

candidate rejected.

---

# 18. COST FILTER

Jika task memiliki:

maximumCost

Router tidak boleh memilih kandidat yang melampaui limit.

Jika pricing:

UNKNOWN

Router mengikuti unknown-cost policy.

Default:

UNKNOWN tidak dianggap FREE.

---

# 19. HEALTH FILTER

Health states:

HEALTHY

DEGRADED

RATE_LIMITED

UNAVAILABLE

UNKNOWN

Default:

UNAVAILABLE

tidak boleh dipilih.

RATE_LIMITED

tidak boleh dipilih sampai cooldown selesai.

---

# 20. CANDIDATE SCORING

Candidate score dapat mempertimbangkan:

- free status
- cost
- quality
- capability
- context
- health
- latency
- priority
- recent failures

Contoh conceptual:

score =

freeScore
+
qualityScore
+
capabilityScore
+
healthScore
+
priorityScore
-
costPenalty
-
latencyPenalty
-
failurePenalty

Implementasi aktual dapat menggunakan weighted scoring.

---

# 21. HARD REQUIREMENTS

Hard requirements harus dipenuhi terlebih dahulu.

Contoh:

Tool calling required.

Model tanpa tool calling:

REJECT

Bukan:

LOW SCORE.

---

# 22. SOFT PREFERENCES

Soft preferences digunakan untuk scoring.

Contoh:

Prefer FREE.

Prefer Mistral.

Prefer fast model.

Prefer low cost.

Model tetap dapat dipilih jika preference tidak tersedia.

---

# 23. PREFERRED MODEL

Profile dapat menentukan preferred model.

Contoh:

Preferred:

Model A

Fallback:

Model B

Model C

Router mencoba:

A

kemudian B

kemudian C.

---

# 24. MAXIMUM FALLBACK

Default:

3 attempts.

Configurable per:

- profile
- agent
- workflow
- task

Maximum fallback harus memiliki hard upper bound.

Tidak boleh infinite.

---

# 25. RETRY VS FALLBACK

RETRY:

Menggunakan candidate yang sama.

FALLBACK:

Berpindah candidate.

Contoh:

Model A / Key A

↓

timeout

↓

RETRY

↓

Model A / Key A

Jika tetap gagal:

Model A / Key B

atau

Model B / Key A

---

# 26. CREDENTIAL ROTATION

Credential rotation dilakukan jika:

- rate limit
- temporary credential failure
- provider throttling

Example:

Key A

↓

429

↓

Key B

↓

success

---

# 27. CREDENTIAL SELECTION

Credential ranking:

1. ACTIVE
2. NOT COOLDOWN
3. HEALTHY
4. priority
5. recent success

---

# 28. COOLDOWN

Credential yang rate-limited masuk:

COOLDOWN

Selama cooldown:

Router tidak memilih credential tersebut.

Setelah cooldown:

credential dapat dicoba kembali.

---

# 29. COOLDOWN BACKOFF

Cooldown dapat menggunakan:

exponential backoff

dengan maximum limit.

Contoh:

30 sec

↓

60 sec

↓

120 sec

↓

maximum configured cooldown

---

# 30. PROVIDER FAILOVER

Jika seluruh credential provider gagal:

Example:

Provider A

↓

Key A fail

↓

Key B fail

↓

Provider B

↓

Key C

↓

Model B

# 32. MODEL PRIORITY

# 33. PROFILE FALLBACK LIMIT

# 73. PROVIDER PREFERENCE

Require Mistral

maka provider lain tidak valid.

# 74. MODEL PREFERENCE

Preferred model bukan hard requirement secara default.

Jika preferred model unavailable:

fallback allowed.

# 75. FREE-FIRST POLICY

↓

↓

# 76. BALANCED POLICY

AUTO_BALANCE:

Router dapat memilih paid model jika peningkatan kualitas dianggap sepadan dengan cost policy.

Namun router tidak boleh melewati:

maximumCost.

---

# 77. BYOK POLICY

AUTO_BYOK:

Hanya credential user.

---

# 78. MANUAL POLICY

MANUAL:

No automatic model switch.

No automatic provider switch.

Jika user hanya memilih provider/model tanpa credential:

active credential dapat digunakan.

# 106. DEFINITION OF DONE

AI Router dianggap selesai apabila:

- four routing modes work
- candidate filtering works
- candidate scoring works
- multiple API keys work
- credential rotation works
- model fallback works
- provider fallback works
- retry works
- cooldown works
- capability matching works
- context matching works
- cost policy works
- manual mode is strict
- routing decision is observable
- secrets never leak
- no infinite loops
- tests pass
