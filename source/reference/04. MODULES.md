# HUMAN CLI — MODULES

Version: 1.0.0
Status: ACTIVE
Owner: Dhani Yuliawan
Project: Human CLI
Platform: Android
Minimum OS: Android 7.0 / API 24
Primary Target: Android 10 / RAM 4 GB

---

# 1. PURPOSE

MODULES.md mendefinisikan seluruh module utama Human CLI.

Dokumen ini digunakan sebagai:

- implementation map
- dependency map
- development sequence
- module ownership
- testing boundary
- AI handover reference
- anti-scope-drift reference

Setiap module harus memiliki tanggung jawab yang jelas.

AI tidak boleh memindahkan tanggung jawab module secara sembarangan.

---

# 2. MODULE PRINCIPLES

Setiap module harus:

- memiliki tanggung jawab spesifik
- memiliki interface yang jelas
- dapat diuji secara independen
- tidak membuat circular dependency
- tidak menyimpan secret secara plaintext
- tidak mengakses module lain secara langsung jika abstraction tersedia

---

# 3. MODULE STATUS

Allowed status:

NOT_STARTED
IN_PROGRESS
IMPLEMENTED
TESTING
PASSED
FAILED
BLOCKED
FROZEN

Default:

NOT_STARTED

Module yang sudah PASSED dapat ditandai:

FROZEN

Module FROZEN tidak boleh diubah tanpa alasan yang valid.

# 29. MODULE TEST REQUIREMENT

Setiap module harus memiliki:

- error tests
- edge case tests
- integration tests jika mempunyai external dependency

- authentication test

- failure test

- generation test

# 30. DEFINITION OF DONE

Module dianggap DONE apabila:

1. Implementation selesai.
2. Tidak ada TODO kritis.
3. Tidak ada fake implementation.
4. Error handling tersedia.
5. Security requirement terpenuhi.
6. Persistence benar jika diperlukan.
7. Test berhasil.
8. Integration berhasil jika diperlukan.
9. UI behavior benar jika module memiliki UI.
10. BUILD_STATE diperbarui.

# 31. NO HIDDEN DEPENDENCY

Module tidak boleh bergantung pada:

- undocumented global state
- hardcoded credentials
- hidden API
- undocumented provider behavior
- UI state sebagai database
- temporary variable sebagai persistent state

Semua dependency harus jelas.

# 39. PROVIDER FAILURE RULE

Jika provider gagal:

Router mencoba fallback sesuai mode.

Namun:

MANUAL mode:

Tidak boleh silent switch.

AUTO modes:

Fallback diperbolehkan sesuai policy.

Setiap fallback harus tercatat pada task metadata.

---

# 40. MODEL CHANGE RULE

Jika model berubah:

Do not restart project.

Do not recreate project.

Do not discard context.

Load:

- project
- active task
- handover
- relevant context
- state

Then continue.

---

# 41. CONNECTOR FAILURE RULE

Jika connector gagal:

Task harus berhenti dengan status:

CONNECTOR_ERROR

Jangan berpura-pura berhasil.

Retry hanya jika error retryable.

---

# 42. SANDBOX FAILURE RULE

Jika sandbox gagal:

Task:

FAILED

atau

RECOVERABLE

Jika workspace masih valid:

resume dapat dilakukan.

Jika sandbox destroyed:

recreate sandbox dan restore required state.

---

# 43. WORKFLOW FAILURE RULE

Workflow harus menyimpan:

- last completed step
- current step
- error
- retry count

Resume tidak boleh mengulang seluruh workflow jika tidak diperlukan.

---

# 44. AGENT FAILURE RULE

Jika Agent gagal:

Record:

- task
- model
- provider
- error
- tools called
- last successful step

Agent dapat di-resume atau retry.

# 45. UI FAILURE RULE

UI error tidak boleh merusak persistent task state.

Jika UI crash/restart:

task state tetap dapat dipulihkan.
