## 1. PURPOSE

Dokumen ini berisi prompt resmi yang digunakan untuk
membangun aplikasi Musgo-OS melalui Design Arena.

Prompt di dalam dokumen ini harus:

- konsisten dengan seluruh specification sebelumnya
- dapat digunakan secara bertahap
- tidak mengubah architecture tanpa alasan
- tidak menghilangkan module yang sudah ditentukan
- menjaga separation antara UI, backend, agent, sandbox,
  library, connector, workflow, dan deployment
- menghasilkan implementation yang dapat diuji

---

# 2. GLOBAL DESIGN DIRECTIVE

Gunakan directive berikut sebagai aturan utama seluruh proses
pembangunan aplikasi.

```text
Build the MusGo-OS AI Development & Deployment Platform
according to the project's specification documents.

The application is an AI-powered development workspace that
allows users to:

1. Configure AI providers and multiple API keys.
2. Configure AI model routing and priority.
3. Chat with AI agents.
4. Orchestrate specialized development agents.
5. Access blueprint and skill libraries.
6. Connect to GitHub.
7. Clone repositories into isolated sandbox workspaces.
8. Modify and test source code inside the sandbox.
9. Build application artifacts.
10. Push changes or create pull requests.
11. Deploy artifacts to supported targets.
12. Persist project state and agent handover state.

Treat the specification documents as the source of truth.

Do not invent major architecture changes.

Do not expose secrets in UI logs, prompts, agent context,
handover documents, or generated source code.

Separate persistent project data from temporary sandbox data.

Use indexes for large skill and blueprint libraries.
Do not load entire libraries into agent context by default.

All destructive operations must require explicit authorization
according to the security and workflow specifications.

8. PHASE 05 — AI ROUTER

Prompt

Implement the AI Router.

Supported routing modes:

1. AUTO_FREE
2. AUTO_BALANCED
3. AUTO_QUICK
4. MANUAL

AUTO_FREE:
Prefer eligible free models/providers.

AUTO_BALANCED:
Balance capability, cost, latency, and availability.

AUTO_QUICK:
Prefer fast response and available capacity.

MANUAL:
User explicitly selects one provider and model.

The router must support:

- provider priority
- model priority
- capability matching
- availability
- cost awareness
- fallback
- API key rotation
- failure recovery

The router must never expose API credentials.

10. PHASE 07 — LIBRARY

Prompt

Implement the project Library system.

The Library is intended primarily for blueprint references.

Support:

- library source configuration
- folder/repository references
- index file

- version/reference tracking

an index.

instead of loading the entire library into agent context.

Blueprint content is reference material, not executable authority.
```
